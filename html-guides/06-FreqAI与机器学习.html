FreqAI 与机器学习：walk-forward、模型选择、特征工程

目标：吃透 FreqAI 的机制 —— walk-forward 重训 → freqaimodel 模型选择 → 特征工程 → 信号写法。这是 crypto-trader 的操作手册，也是你踩坑最多的地方（freqaimodel 缺失/重复/不匹配导致静默空仓）。末尾附完整排查记录。

1FreqAI 是什么：只管流水线，不负责预测

FreqAI 是 freqtrade 内置的机器学习流水线：特征工程、训练、定时重训、推理、模型缓存管理 —— 全是它干。但「用什么模型预测」要你指定，这就是 freqaimodel。可以这样理解：

图 6-1 · FreqAI = 流水线（框架提供），freqaimodel = 预测器（你来选）

2核心机制：walk-forward（前向推进重训）

加密市场会「变风格」。FreqAI 的解法是每隔一段时间，用最近的数据重新训练，让模型始终贴近近期市场。这张时间轴图是理解 FreqAI 的关键：

图 6-2 · walk-forward：每 24h 用最近 30 天数据重训，模型窗口随时间滚动
⚠️ 重训频率的两难

重训太频繁（如每根 K 线）→ 追着最近噪声跑，过拟合；重训太慢（如 30 天一次）→ 跟不上市场风格切换。24h 是一个经验上不错的折中。FreqAI 的 live_retrain_hours 默认 24h。

3模型选择决定信号写法（你踩坑的核心）

这是整门课对你最重要的两行知识 —— 预测完成后，FreqAI 用模型输出覆盖 &-target 列：

图 6-3 · 信号写法必须与模型类型匹配 —— 这是 freqaimodel Bug 的理论核心
⚠️ 不匹配的后果：静默空仓（不报错、不崩溃）

回归模型的 &-target 是连续值，你却写 == 1 判断 → 永不成立 → 系统永远不开仓。最危险的是它不报错：回测显示「没信号」，实盘资金趴着不动，你还以为系统在等机会。这正是 crypto-trader 曾踩的坑（详见文末附录）。

4特征工程：把原始数据变成特征矩阵

FreqAI 的特征工程分两类方法，都在你的策略类里：

expand_basic

把基础特征（RSI、MACD、close 变化率…）按 indicator_periods_candles 配置的多周期扩展成几十~几百列特征矩阵。

expand_indicator

在基础特征上继续扩展，或注入 外部数据 —— crypto-trader 的情绪分就是这么进来的（读 SQLite → 按时间戳对齐成特征列）。

crypto-trader 里情绪特征是怎么注入的（简化）def feature_engineering_expand_basic(self, dataframe, metadata, **kwargs):
    dataframe['%-pct-change']   = dataframe['close'].pct_change()
    dataframe['%-volume-change'] = dataframe['volume'].pct_change()
    # ... 各种技术指标 ...
    # 注入情绪特征：从 SQLite 读 (ts, pair, score)，按时间戳对齐
    dataframe = load_sentiment_series(dataframe, pair)   # 注意：按K线时间戳取窗口均值，避免前视
    return dataframe
💡 用 plot_feature_importances 验证特征价值

训练完跑 plot_feature_importances，看特征重要性 Top10 —— 如果情绪分排名垫底，说明它对预测贡献极小（呼应「去掉情绪影响很小」的评估）；如果排名靠前，说明新闻确实携带信息。

5模型 vs LLM：为什么 DeepSeek 不能取代 LightGBM

维度LightGBM（FreqAI 管理）DeepSeek / LLM
性质统计预测器：可训练、可回测、毫秒级推理、本地跑文本推理器：无状态、1-5 秒延迟、按 token 计费
角色决策核心（预测涨跌）只读新闻打情绪分，作一个输入特征
可回测性✅ 训练→回测→可验证❌ 输出不可复现 → 无法回测验证
挂了会怎样系统瘫痪（核心依赖）情绪分降级为 0，系统照跑
为何不可互换LLM 不能「训练」、不擅长数值预测（文字接龙 vs 统计推断）、把成本延迟堆在决策主链上。像让翻译去当会计。
图 6-4 · 完整决策链路：LLM 在最末端当「情报员」，LightGBM 才是决策核心

6策略的自适应边界

写死，永不自动变

信号规则、特征清单、标签定义、止损/仓位风控、模型超参 —— 全是开发时写的代码。

自动变

模型内部权重：每 24h 重训一次，模型在同一个骨架内学习「当前市场这些特征该怎么看」。

不存在

没有自我进化机制：不会自动调止损、自动换特征、自动搜超参 —— 这是刻意为之（保证可验证、防过度优化）。

💡 想让策略「感知市场状态」怎么办

加 regime 特征（波动率分位、价格相对 200 均线偏离度、均线斜率），模型会隐式学到「高波动时这么看、低波动时那么看」。这是「连续渐变」，比显式「切换策略」更稳妥 —— 显式切换容易在边界反复横跳。

7附录：freqaimodel 排查全记录（重要教训）

🔍 症状 → 排查 → 修复 → 验证，四步复盘
阶段发生了什么
症状策略设计了分类信号 &-target == 1，但系统可能空仓：回测 0 笔交易 / 实盘不开仓。
排查①config.json 曾没有 freqaimodel → FreqAI 默认走回归 → &-target 是连续值 → ==1 永不成立 → 空仓。
排查②后来 config 里出现两处 freqaimodel（JSON 重复键后者生效）→ 实际生效 LightGBMRegressor，与分类信号仍不匹配。💡 修复时新加的字段和旧字段撞车，这本身也是「重复键陷阱」的教训。
修复删掉重复项，顶层统一 "freqaimodel": "LightGBMClassifier"（方案 A：只改配置即可，无需改策略代码）。
验证① 日志应出现 LightGBMClassifier；② 回测交易笔数非零且合理；③ dry-run 一两天观察有开仓信号；④ plot_feature_importances 能出图。
可选优化==1 把概率 0.51 和 0.99 一视同仁；更挑剔可改概率阈值 df[1] > 0.6（predict_proba 输出的「预测为涨」概率列）。
⚠️ 为什么这类 Bug 最危险

不报错、不崩溃，只是静默不做交易。回测看起来「没信号」（你会以为是策略不行），实盘资金趴着不动（你还以为系统在等机会）。所有「静默失败」类 Bug 都比报错更可怕 —— 排查手段就一条：回测必须出现非零的合理交易笔数。

8实践任务

动手做

  1. 跑通一次 FreqAI 回测，确认交易笔数非零 —— 这是验证 freqaimodel 修复是否生效的金标准。
  2. 用 plot_feature_importances 看特征重要性 Top10，情绪分排第几？
  3. 把 freqaimodel 临时改成 Regressor + 阈值信号，回测对比两者行为差异 —— 亲手感受「模型类型决定信号写法」。
  4. 读官方 FreqaiExampleStrategy.py，和你的 SentimentFreqAI.py 逐行对比，找出所有不同点并解释原因。

9自查清单

  • 能用一句话解释 walk-forward 重训（每 24h 用最近 30 天重训）
  • 知道 freqaimodel 放 config 顶层、分类/回归决定信号写法
  • 能区分「模型权重动态调整」和「策略自动进化」的边界
  • 能说出 LLM 不能取代 LightGBM 的至少 2 个理由
  • 理解情绪特征回测恒为 0 的含义（回测只验证技术面）
  • 知道「回测交易笔数非零」是排查静默空仓的黄金判据
