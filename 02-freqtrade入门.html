freqtrade 入门：策略如何被「叫醒」

目标：搞懂 freqtrade 的运行骨架 —— 策略生命周期、config.json、常用命令、dry-run 与实盘的区别。这是 crypto-trader 的操作手册：你的 SentimentFreqAI.py + config.json 就是它的全部输入。

2策略生命周期：三个 populate 回调

freqtrade 是一个事件驱动框架：每当一根新 K 线到达（或定时器触发），引擎就按固定顺序调用你策略里的三个方法。看懂这张时序图，就懂了 freqtrade 的一半。

图 2-2 · freqtrade 策略生命周期：三个 populate 回调 + 引擎执行 + 附加回调
💡 关键领悟：策略是「填表」，不是「下单」

新手常误以为要在策略里调 API 下单。实际上你只负责往 dataframe 里填 enter_long / exit_long 列（0 或 1），真正下单、止损、记录是引擎干的。这让回测和实盘能共用同一套策略代码 —— 这就是 freqtrade 最大的价值。

3config.json 骨架

图 2-3 · config.json 关键键位：项目实际值都标出来了
⚠️ 两个最容易踩的配置坑
  1. startup_candle_count 必须 ≥ 最大指标窗口：如果你用了 200 日均线，预热少于 200 根，指标会全是 NaN，信号全失效。你项目用 950，是因为 FreqAI 特征窗口大。
  2. freqaimodel 是顶层键（与 freqai 平级），不在 freqai 段里！JSON 重复键时后者生效 —— 你项目曾因 config 里出现两个 freqaimodel 导致回归模型悄悄覆盖了分类模型（详见 STEP ⑥）。

4常用命令与它们的关系

命令干什么什么时候用
download-data下载历史 K 线到本地回测/训练前；FreqAI 需 30 天+，别漏 --days
backtesting用历史数据模拟跑策略验证策略逻辑（注意：FreqAI 会在回测中训练）
trade启动实盘 / dry-run 运行最核心命令；--dry-run 默认，切实盘需改 config
hyperopt自动搜索最优参数STEP ⑦ 详解
plot-dataframe画出 K 线 + 买卖信号肉眼检查策略行为是否正确

dry-run vs 实盘：本质区别

dry_run = true

引擎假装下单：走完整决策流程，但订单不真正发到交易所。资金是虚拟的。日志里每笔「成交」都是模拟。

dry_run = false

真实下单，用你交易所账户的真钱。API key 需有交易权限，币在交易所账户里。

🔐 切换实盘前三查
  1. dry_run: false 确认改了（而不是靠记忆）
  2. stoploss、stake_amount 已按风险调好
  3. API key 已绑定交易所子账户 + IP 白名单 + 仅交易权限（无提现权）

5项目映射：怎么读你自己的项目

阅读 crypto-trader 的顺序建议：config.json → strategies/SentimentFreqAI.py → deploy.sh。

  • SentimentFreqAI.py 就是上面生命周期三个 populate 回调的实现，外加 FreqAI 的 feature_engineering_* 与 set_freqai_targets
  • config 顶层键 freqaimodel: LightGBMClassifier —— 曾因缺失/重复/与信号不匹配导致静默空仓（完整排查见 06）
  • deploy.sh 里封装了 download-data / backtest / trade 等常用命令，Windows 环境变量动态找 python

6实践任务

动手做（在 WSL2 的 crypto-trader 环境）

  1. 逐行读 config.json，给每个键写一行注释 —— 读不懂的先查官方配置文档。
  2. 用官方模板跑一次回测确认链路通：官方示例在 freqtrade/templates。
  3. 在示例策略上改一个参数（如均线周期），观察回测结果怎么变 —— 感受「参数敏感性」。
  4. 跑 freqtrade trade --dry-run 10 分钟，观察日志里策略回调被调用的节奏。

7自查清单

  • 能说出三个 populate 回调的调用顺序与职责
  • 理解「策略只填 0/1 信号，引擎负责执行」的心智模型
  • 知道 dry_run 与实盘的区别、切换前要查什么
  • 能解释 startup_candle_count 为什么要大于指标窗口
  • 知道 freqaimodel 应放 config 顶层、曾因重复键踩坑
