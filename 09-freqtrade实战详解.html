A. K线与技术指标

缩写全称通俗解释典型用法
K线Candlestick（蜡烛图）一根柱子记录一段时间内的开/高/低/收四个价格（OHLC）+ 成交量。15m K线 = 每 15 分钟结一根。K线是所有技术分析和回测的最小数据单元。freqtrade 的一切都围绕K线表展开
OHLCVOpen, High, Low, Close, VolumeK线的五个数据列：开盘价、最高价、最低价、收盘价、成交量。dataframe 自带的五列
MAMoving Average（移动平均）最近 N 根K线收盘价的算术平均，连成线。它抹平噪音、显出趋势方向。缺点：对每根K线一视同仁，新数据来得慢。MA20 = 最近 20 根的均价线
EMAExponential Moving Average（指数移动平均）MA 的改良版：给越新的K线越大的权重，对价格变化反应更快。代价是更容易被短期噪音干扰。「EMA12 > EMA200」即经典的金叉判断大趋势向上。第 6 节策略的快慢线
RSIRelative Strength Index（相对强弱指标）衡量「最近一段时间涨的力气 vs 跌的力气」，输出 0~100 的数。传统解读：<30 超卖（跌过头，可能反弹）、>70 超买（涨过头，可能回调）。本质是找「趋势中的回调买点」。第 6 节策略的入场过滤
ATRAverage True Range（平均真实波幅）最近 N 根K线「平均一根能波动多宽」，单位是价格本身。它不看方向、只看波动的剧烈程度——用来给止损定宽度：波动大的币止损放宽，波动小的收紧。05 篇的波动率止损
金叉/死叉Golden Cross / Death Cross快线从下往上穿越慢线 = 金叉（转多信号）；反之为死叉（转空信号）。EMA12/EMA200 组合
超买/超卖Overbought / Oversold价格短期涨/跌得太猛，动能透支，反向修正概率增大。常用 RSI 阈值判定（70/30）。RSI 应用场景

B. 交易与收益术语

缩写全称通俗解释典型用法
ROIReturn on Investment（投资回报率）收益 ÷ 成本。0.06 = 6%。freqtrade 里的 minimal_roi 是一张阶梯止盈表：持仓越久，触发平仓的利润门槛越低——赚 6% 立刻走，套了 3 小时后赚 1% 也走。第 6 节退出规则
做多/做空Long / Short做多 = 先买后卖，赌涨；做空 = 先借币卖出、跌了买回还币，赌跌。现货只能做多（can_short=False），合约两者皆可。enter_long / enter_short 列
开仓/平仓Open / Close Position开仓 = 建立一笔持仓（买入）；平仓 = 结束这笔持仓（卖出落袋）。一买一卖之间盈亏结算。entry / exit 回调
止损Stop Loss亏损达到预设线（如 -5%）无条件强制平仓，切断单笔最大损失。是「活得久」的第一道保险。stoploss = -0.05
追踪止损Trailing Stop止损线不固定，而是跟着最高价往上爬：涨得越高，锁定的利润越多；一旦从高点回撤一定幅度立刻平仓。「涨了保住利润，跌了自动逃跑」。trailing_stop 三参数
回撤Drawdown账户从最高点跌下来的最大幅度。年赚 100% 但中途回撤 80%，大概率活不到终点——所以报表里 Max drawdown 比收益率更值得盯。回测报表核心指标
滑点Slippage你计划成交的价格 vs 实际成交价格的差。下单瞬间价格变了、或深度不够吃多档，都会产生滑点。回测默认无滑点，所以回测收益天然偏乐观。entry_pricing 配置
订单簿Order Book交易所里「谁在什么价位挂了买单/卖单」的实时列表。买一/卖一（bid/ask）= 离成交价最近的两档。price_side: other 就是挂对手档价，保证立刻成交。entry_pricing 配置
限价单/市价单Limit / Market Order限价单 = 指定价格挂单（可能不成交）；市价单 = 按当前盘口立刻成交（价格不受控）。freqtrade 用「越过盘口一档的限价单」折中：近似市价的速度 + 限价的价格保护。order_type 配置
现货/合约Spot / Futures现货 = 真实买卖币本身；合约 = 交易「未来交割的合同」，带杠杆、可做空、会被强制平仓。风险级别完全不同。trading_mode 控制。trading_mode: spot

C. freqtrade 框架机制术语

术语通俗解释在哪配置
dry-run（模拟盘）引擎完整跑：真实行情、真实信号、真实下单逻辑，唯一区别是订单不进交易所，成交记录存本地 sqlite。检验策略在真实时间流里表现的最后一步，上实盘前的必经关卡。config: dry_run: true
回测（Backtesting）把策略放到历史数据上重放一遍，统计它「如果当时在场会赚多少」。快（几分钟跑几年），但只能逼近、不能替代 dry-run（无滑点、无排队、无情绪）。freqtrade backtesting
白名单（pair_whitelist）允许交易的币种列表。策略只在白名单内的币上找信号。配合 VolumePairList 可按成交量动态筛选。exchange.pair_whitelist
交易对（Pair）「用什么买什么」，如 BTC/USDT = 用 USDT 买 BTC。斜线前是基础币、后是计价币。freqtrade 的 pair 写法统一为 基础/计价。白名单元素
stake（投入额）每笔交易投入多少计价货币。unlimited = 按 max_open_trades 均分可用余额。stake_amount
timeframe（周期）策略主K线周期。15m = 每 15 分钟出一根新K线、做一次完整决策。周期越短交易越频繁、噪音越大。策略类 timeframe
informative pair「参考K线」：主策略跑 15m，但想同时看 1h/4h 大周期指标（如 BTC 的 4h 趋势），就把它声明为 informative——多周期数据合并的机制。informative_pairs()
walk-forward（滚动训练）FreqAI 的训练方式：用「过去 N 天」训练模型 → 预测「未来 M 天」→ 窗口前移重复。模拟真实世界「你永远只有历史数据」的约束，防止用未来数据训练的作弊模型。freqai 配置块
过拟合（Overfitting）模型/参数把历史数据的噪音当规律学了下来——回测完美、实盘即死。参数越多、优化轮数越多越容易过拟合。防线：留出验证段、参数越少越好。03/07 篇详述
hyperopt（超参优化）freqtrade 内置的自动调参：给参数空间，它跑几百轮回测迭代，找损失函数最优的参数组合。是「过拟合制造机」，用完必须留独立数据验证。freqtrade hyperopt
💡 一句话记忆版

EMA=加权平均线看趋势，RSI=涨跌力气对比找回调点，ROI=利润率（阶梯止盈的门槛），止损=亏损刹车，回撤=从山顶跌多深，滑点=计划价与成交价的差，dry-run=全真模拟不花真钱。

2.3 代理：WSL2 访问 Binance 的关键

WSL2 有两种网络模式，代理写法不同——这是你环境里最常见的坑：

WSL2 网络模式代理地址写法怎么确认自己是哪种
mirrored 镜像模式127.0.0.1:7897（与 Windows 共享回环）curl -x http://127.0.0.1:7897 https://api.binance.com/api/v3/ping 通了就是 mirrored；
再试 cat /etc/resolv.conf 看 nameserver 是否 10.x.x.x（NAT 特征）
NAT 模式（默认）http://<Windows主机IP>:7897，主机 IP 可用 ip route | grep default 取网关地址
# 快速验证代理连通性（WSL2 内）
curl -x http://127.0.0.1:7897 -sS https://api.binance.com/api/v3/ping
# 返回 {} 即通；超时/拒绝 → 检查模式与防火墙
⚠️ 代理三连坑
  1. 终端代理 ≠ freqtrade 代理：即使 export https_proxy=...，freqtrade 底层的 aiohttp 也经常不认——必须在 config.json 的 exchange.ccxt_config 里显式写 aiohttp_proxy（第 4 节）。
  2. 代理软件要开「允许局域网连接」（Allow LAN），否则 NAT 模式下 Windows 防火墙外的请求全被拒。
  3. dry-run 只走公开行情接口，不需要 API Key；但代理断了 bot 会连续报 NetworkError，所以代理本身就是 dry-run 的单点故障。

4.1 最容易配错的 6 个键

键常见错误正确姿势
aiohttp_proxy只配了终端环境变量，没写进 config写进 exchange.ccxt_config，这是唯一可靠的位置
startup_candle_count给 100，指标实际需要 950 → 信号错乱= 最长指标回看窗口 + 裕量（你的项目应约 950）
max_open_trades设太大，模拟资金被摊薄到每笔几十刀资金/预期单笔 stake 再取整，3 左右合适
pair_whitelist 与 pairlists 冲突VolumePairList 会覆盖手写白名单想固定币对就用 StaticPairList，想动态就删白名单
listen_ip_address写成 0.0.0.0 暴露到局域网本机调试一律 127.0.0.1
freqai 配置重复策略类和 config 各有一份 freqai 块只留 config 一份（你项目 review 里的 17 号坑）
💡 freqai 块：dry-run 模式下的关键项
  • train_period_days：每次训练用多少历史（30-60 天常见）
  • backtest_period_days：回测中每次重训覆盖多久（7 天起步）
  • expiration_hours：实盘/dry-run 模型过期时间，过期自动重训。你的机器无 GPU，设 24 而不是 6，否则一天全量重训 4 次，CPU 扛不住
  • identifier：模型命名空间，改特征后必须换新 identifier，否则读到旧模型
  • fit_live_training_candles：实盘训练时额外掺入的实时K线数（0-400）

5数据管理：download-data 全解

回测和 FreqAI 训练都吃本地数据。数据不在本地，一切免谈。

# 下载 BTC/ETH 的 15m K线，180 天，USDT 计价
freqtrade download-data \
  --exchange binance \
  --pairs BTC/USDT ETH/USDT \
  --timeframes 15m 1h \
  --days 180 \
  --userdir user_data \
  # 代理同样要在 config 里配好，或加 --config 指向你的配置

# FreqAI 常用：多周期特征 + 更长历史（训练窗口长）
freqtrade download-data -c config.json --timerange 20260501- --timeframes 5m 15m 1h 4h

# 查看本地已有哪些数据
freqtrade list-data --userdir user_data

# 数据格式转换（feather 是默认且最快）
freqtrade convert-data --format-from json --format-to feather \
  --pairs BTC/USDT -t 15m --timeframes 15m
参数含义经验值
--days N最近 N 天普通回测 90-180；FreqAI ≥ train+backtest 总量
--timerange A-B精确区间，如 20260401-20260701复现实验必用（--days 会随日期漂移）
--timeframes多周期一次拉齐策略里 informative 用什么周期就下什么
--prepend往更早的方向补数据扩展历史而不重下
⚠️ 数据坑两条
  1. 数据不足 ≠ 报错：FreqAI 训练数据不够时常常静默出空模型或回测 0 交易——你的 deploy.sh 曾需要 --days 120 就是这个原因。
  2. 回测期间别删 data/：换个目录或清理磁盘时，data/ 是可以重新下载的（可再生），但 freqaimodels/ 删了就要重训。

6手写一个完整策略（从头到尾 · 逐行注释版）

不管多复杂，一个策略文件 = 一个类 + 固定骨架。本节代码可直接跑，每一行都有注释。先把代码里出现的 3 个专业名词讲清，再看代码。

📖 读代码前：3 个专业名词（不是通用词，是 freqtrade 术语）
  1. INTERFACE_VERSION（策略接口版本）——freqtrade 官方术语，全称「Strategy Interface Version」。它声明你的策略用哪套回调协议。历史上改过版：v1 旧协议用 buy/sell 列和 buy_trend/sell_trend 方法（已废弃）；v3 即所谓「现代接口」（官方称 modern strategy interface），统一用 enter_long / exit_long / enter_short / exit_short 四列 + populate_entry_trend / populate_exit_trend 方法。freqtrade 2026.7 一律写 3，老教程里用 v1 的代码抄来直接报错。
  2. metadata（元数据）——每个回调收到的第二个参数，一个字典，形如 {'pair': 'BTC/USDT'}。作用：告诉你当前这张K线表属于哪个币（引擎会逐个币种调用同一策略）。
  3. space（参数空间）——hyperopt 优化术语（见 07 篇）。声明一个参数属于哪段逻辑：buy=入场参数、sell=出场参数、protection=防护参数。跑 hyperopt --spaces buy 时，引擎只调 space='buy' 的参数。
user_data/strategies/MyFirstStrategy.py
# ================= 导入：4 行，各管一件事 =================
from pandas import DataFrame        # DataFrame = pandas 的「表格」类型。freqtrade 把一个币种的
                                  # 全部K线装进一张表传给你：每行=一根K线，列=open/high/low/close/volume
import talib.abstract as ta         # TA-Lib = 老牌技术指标计算库。「as ta」起短名，
                                  # 下文 ta.EMA() / ta.RSI() 都是调用它算好的指标函数
from freqtrade.strategy import IStrategy, IntParameter
                                  # IStrategy = 策略基类（必须继承，引擎靠它找到你的回调）
                                  # IntParameter = 整数型可优化参数（给 hyperopt 调参用）
from freqtrade.persistence import Trade
                                  # Trade = 一笔持仓交易的对象（含开仓价、金额、时间），
                                  # 后面动态止损回调里会用到


class MyFirstStrategy(IStrategy):    # 定义策略类并继承 IStrategy。类名 = --strategy 参数的值；
                                  # 文件名 MyFirstStrategy.py 建议与类名完全一致
    """EMA 趋势 + RSI 过滤：均线定方向，RSI 等回调买点"""

    # ============ ① 协议声明 ============
    INTERFACE_VERSION = 3           # 接口版本号（见上方名词①）：声明用 v3 现代接口

    # ============ ② 引擎行为参数 ============
    timeframe = '15m'              # 主K线周期：15分钟。策略类里的值覆盖 config.json 里的同名项
    can_short = False              # 是否允许做空。现货必须 False（合约才可能 True）
    startup_candle_count = 210     # 引擎调用策略前，先额外喂 210 根历史K线「预热」，
                                # 保证 EMA200 在第一天就有值。规则 = 最长指标窗口(200) + 裕量(10)
    process_only_new_candles = True
                                # 只在「新K线收盘」时计算，盘中 Tick 不重复算：
                                # 省 CPU，且信号不会因盘中波动反复横跳

    # ============ ③ 退出规则：ROI 阶梯 + 固定止损 + 追踪止损 ============
    minimal_roi = {              # ROI（投资回报率）阶梯止盈表：
                                 # 键 = 持仓分钟数（字符串），值 = 收益率门槛
        '0': 0.06,            # 开仓后任何时刻达到 +6% → 平仓
        '60': 0.03,           # 持满 60 分钟后，门槛降到 +3%
        '180': 0.01,          # 持满 180 分钟后，门槛降到 +1%
    }                            # 含义：利润要让时间换空间，但空间随时间递减
    stoploss = -0.05             # 固定硬止损：浮亏到 -5% 强制平仓（-0.05 = -5%）
    trailing_stop = True         # 开启追踪止损：盈利后止损线跟随最高价上移
    trailing_stop_positive = 0.015
                                # 追踪生效后的回撤宽度：从最高点回落 1.5% 就平仓
    trailing_stop_positive_offset = 0.03
                                # 激活门槛：浮盈超过 +3% 才启动追踪（防止刚开仓就被震出去）
    trailing_only_offset_is_reached = True
                                # 未到 +3% 之前，仍用固定 -5% 止损（两个机制各管一段）

    # ============ ④ 可优化参数 ============
    buy_rsi = IntParameter(20, 45, default=30, space='buy')
                                # RSI 入场阈值：hyperopt 搜索范围 20~45，平时默认 30
                                # space='buy' 声明它属于入场规则（见上方名词③）

    # ===== ⑤ 三个 populate 回调：引擎每根新K线依次调用（见 02 篇时序图）=====
    def populate_indicators(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        # 回调 1/3：算指标。参数 dataframe = 当前币种的K线表；
        # metadata = 元数据字典，metadata['pair'] 是当前币名（见名词②）
        dataframe['ema_fast'] = ta.EMA(dataframe, timeperiod=12)
        # 用收盘价算 12 周期指数均线（快线），结果存为新列 'ema_fast'
        dataframe['ema_slow'] = ta.EMA(dataframe, timeperiod=200)
        # 200 周期慢线，判断大趋势方向
        dataframe['rsi'] = ta.RSI(dataframe, timeperiod=14)
        # 14 周期 RSI 相对强弱指标（0~100，低于 30 一般视为超卖）
        return dataframe          # 把加完列的表还给引擎。铁律：本函数只加列，不做买卖决策

    def populate_entry_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        # 回调 2/3：填入场信号。哪些行满足条件，就把它们的 enter_long 列置 1
        dataframe.loc[           # .loc[行筛选器, 列名] = 值 —— pandas 定位赋值语法
            (dataframe['ema_fast'] > dataframe['ema_slow']) &
            # 条件1：快线 > 慢线 → 处于上升趋势（& = 且）
            (dataframe['rsi'] < self.buy_rsi.value) &
            # 条件2：RSI 低于阈值 → 只在回调超卖时买，不追高。
            # self.buy_rsi.value 取第④块参数的当前值（平时 30，hyperopt 时会被替换成候选值）
            (dataframe['volume'] > 0),
            # 条件3：该根K线有成交量，排除停盘/数据异常行
            # 注意：多条件必须写 & 不能写 and（pandas 语法限制），且每个条件必须加括号
            'enter_long'           # 目标列：v3 接口的入场信号列（做空另有 enter_short）
        ] = 1                   # 满足的行置 1 = 触发买入；没满足的行保持默认 0 = 不操作
        return dataframe

    def populate_exit_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        # 回调 3/3：主动离场信号。与 ROI/止损并行 —— 三者任一先触发都平仓
        dataframe.loc[
            (dataframe['ema_fast'] < dataframe['ema_slow']),
            # 快线下穿慢线 → 趋势反转，主动离场（不等 -5% 止损）
            'exit_long'            # 离场信号列
        ] = 1
        return dataframe

    # ============ ⑥ 进阶回调（可选，用到再写）============
    def custom_stoploss(self, pair: str, trade: Trade, current_time,
                          current_rate: float, current_profit: float, **kwargs) -> float:
        # 动态止损：引擎检查持仓时调用，返回值 = 新的止损线
        # pair = 币种；trade = 当前这笔交易对象；current_rate = 现价；
        # current_profit = 当前浮盈（0.05 = +5%）；**kwargs = 预留的扩展参数（接住即可，不用管）
        if current_profit > 0.04:   # 浮盈超过 +4%：
            return 0.01          # 止损线上移到「保本 +1%」——注意正数 = 锁定盈利
        return self.stoploss       # 否则维持类属性里那个固定 -5%

    def confirm_trade_entry(self, pair: str, order_type: str, amount: float,
                               rate: float, time_in_force: str, current_time,
                               entry_tag, side: str, **kwargs) -> bool:
        # 下单前的最后一道闸：返回 False 可否决这笔开仓
        # amount = 计划买入数量；rate = 计划成交价；order_type/time_in_force = 订单类型与有效方式；
        # entry_tag = 入场标签；side = 方向（'long'/'short'）
        # 典型用法：在这里读外部数据做二次过滤（你的 SentimentFreqAI 就是在这类位置读情绪分）
        return True               # 放行

6.1 dataframe 里的关键列速查

列名谁加的含义
date / open / high / low / close / volume引擎K线五要素 + 时间戳，你进来前就有
ema_fast / ema_slow / rsipopulate_indicators你加的指标列，后两个回调可直接用
enter_longpopulate_entry_trend1=买入信号（v3 现代接口专用列名）
exit_longpopulate_exit_trend1=卖出信号
enter_tag你自己（可选）入场理由标签，回测报表里按 tag 分组分析哪个信号最赚
📌 新手最常犯的三个策略 Bug
  1. 严格相等判断连续值：像 df['&-target'] == 1 判回归器输出——你项目的 P0 坑。连续值要用阈值：df['pred'] > 0.01。
  2. 未来函数：指标里用了 shift(-1) 或未来窗口。回测起飞、实盘暴毙。
  3. minimal_roi 全 0 甩锅：全 0 表示「任何利润立即平仓」，不是「不平仓」。不想用 ROI 就设大值如 {"0": 100}。

11dry-run → 实盘：上真钱前的清单

🚦 上实盘 Gate（全部打勾才动真钱）

  • dry-run 连续运行 ≥ 2 周，无中断、无重启丢数据
  • 期间至少 20 笔完整交易（开+平），行为与回测逻辑一致
  • 日志中无未解释的红色报错（NetworkError 偶发可容忍）
  • FreqAI：模型自动重训 ≥ 2 次成功，do_predict=1 占比 > 90%
  • 手续费/滑点设置与目标交易所一致（回测里 0.1% 是底线）
  • 实盘 API Key 只开现货交易权限，禁提币，IP 白名单绑定 VPS
  • 配好 Telegram 告警 + 每日余额快照
  • 写好「一键停止」脚本（停 bot + 撤所有挂单）
  • 首批实盘资金 ≤ 你愿意全亏的数字（建议 < 500 USDT）
✅ 本篇实践任务（在你的 crypto-trader 上做）
  1. 用 2.3 的 curl 验证代理连通，记录自己是 mirrored 还是 NAT 模式。
  2. 对照 4.1 的 6 个易错键逐项检查你的 config.json（尤其 aiohttp_proxy 和 startup_candle_count）。
  3. dry-run 前台跑 30 分钟，对照 8.3 找到 heartbeat / Searching / do_predict 三类日志行。
  4. 打开 FreqUI（install-ui + 127.0.0.1:8080），截图记录当前余额与持仓页。
  5. 把 11 节的清单打印出来贴在显示器旁——它是你上实盘的 Gate。
